# 高可用部署指南

> 课程注册系统 (CRS) 24/7 可用性部署方案

## 架构概览

```
                    ┌─────────────┐
    用户请求 ──────→│  Nginx LB   │
                    │  :80        │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
         ┌────▼────┐  ┌────▼────┐  ┌────▼────┐
         │ App-1   │  │ App-2   │  │ App-3   │
         │ :8080   │  │ :8080   │  │ :8080   │
         └────┬────┘  └────┬────┘  └────┬────┘
              │            │            │
              └────────────┼────────────┘
                           │
                    ┌──────▼──────┐
                    │  MySQL 8.0  │
                    │  :3306      │
                    └─────────────┘
```

**设计目标:**
- 7×24 运行, 停机时间 ≤ 10%
- 3 个 Spring Boot 实例 + Nginx 负载均衡
- 自动重启 + 健康检查
- 非 root 用户运行容器

## 快速启动

### 1. 克隆代码

```bash
git clone <repository-url>
cd cs
```

### 2. 配置环境变量(可选)

创建 `.env` 文件在项目根目录:

```bash
# MySQL 密码(默认: crs123456)
MYSQL_ROOT_PASSWORD=your-strong-root-password
MYSQL_PASSWORD=your-strong-password

# JWT 密钥(必须修改!)
JWT_SECRET=your-very-long-random-secret-key-at-least-32-chars

# 成绩加密密钥(可选,32 字节 Base64,不设则自动生成)
GRADE_ENCRYPTION_KEY=your-base64-encoded-32-byte-key
```

### 3. 构建并启动

```bash
# 构建镜像并启动所有服务
docker compose up -d

# 查看启动状态
docker compose ps

# 查看实时日志
docker compose logs -f
```

### 4. 验证服务

```bash
# 健康检查(Nginx)
curl http://localhost/health

# 健康检查(应用实例)
curl http://localhost/api/health

# Actuator 端点
curl http://localhost/api/actuator/health
curl http://localhost/api/actuator/info
curl http://localhost/api/actuator/metrics
```

启动后访问:
- **系统入口**: http://localhost (Nginx)
- **直接访问实例**: http://localhost:8081 (App-1), :8082 (App-2), :8083 (App-3)
- **MySQL**: localhost:3306

## 常用运维命令

### 查看服务状态

```bash
docker compose ps                          # 所有服务状态
docker compose logs crs-app1               # 查看单实例日志
docker compose logs --tail=100 crs-mysql   # 查看 MySQL 最近 100 行日志
```

### 停止与重启

```bash
docker compose stop                         # 停止所有服务(保留容器)
docker compose start                        # 启动已停止的服务
docker compose restart crs-app1             # 重启单个实例
docker compose restart                      # 重启所有服务
docker compose down                         # 停止并删除容器
docker compose down -v                      # 停止并删除容器和数据卷(⚠️ 清空数据库!)
```

### 扩容与缩容

当前架构使用 3 个独立服务(crs-app1/2/3)。如需更多实例:

```bash
# 方法 1: 修改 docker-compose.yml 增加 crs-app4 服务
# 方法 2: 使用 Docker Swarm 模式(需初始化)
docker swarm init
docker stack deploy -c docker-compose.yml crs
```

### 数据库管理

```bash
# 进入 MySQL 命令行
docker compose exec crs-mysql mysql -u crs -p

# 备份数据库
docker compose exec crs-mysql mysqldump -u root -p crs > backup.sql

# 恢复数据库
docker compose exec -T crs-mysql mysql -u root -p crs < backup.sql
```

## 健康检查配置

### 应用健康检查

`HealthController` 提供以下指标:

| 指标 | 路径 | 说明 |
|------|------|------|
| 数据库连接 | `/api/health` → `database.status` | MySQL 连接状态 |
| 内存使用 | `/api/health` → `memory.heapUsedPercent` | JVM 堆内存使用率 |
| 运行时间 | `/api/health` → `runtime.uptimeFormatted` | 系统运行时长 |
| 用户数量 | `/api/health` → `database.totalUsers` | 总用户数 |
| 选课数量 | `/api/health` → `database.totalEnrollments` | 总选课记录数 |

### Docker 健康检查

- **间隔**: 每 30 秒
- **超时**: 5 秒
- **重试**: 3 次失败后标记为 unhealthy
- **启动等待**: 60 秒(等待应用启动)

### 自动重启策略

所有服务配置 `restart: unless-stopped`:
- 容器崩溃自动重启
- Docker daemon 重启后自动恢复
- 手动 `docker compose stop` 后不会自动重启

## 性能配置

### Tomcat 线程池

```yaml
server.tomcat.threads:
  max: 200        # 最大工作线程数
  min-spare: 10   # 最小空闲线程数
```

### 连接池 (HikariCP)

```yaml
spring.datasource.hikari:
  maximum-pool-size: 20     # 最大连接数
  minimum-idle: 5           # 最小空闲连接
  idle-timeout: 300000      # 空闲超时 (5分钟)
  max-lifetime: 1200000     # 连接最大生命周期 (20分钟)
  connection-timeout: 30000 # 连接超时 (30秒)
```

### JVM 优化参数

```bash
JAVA_OPTS="-XX:+UseG1GC \
  -XX:MaxRAMPercentage=75.0 \
  -XX:InitialRAMPercentage=50.0 \
  -XX:+UseStringDeduplication \
  -Djava.security.egd=file:/dev/./urandom \
  -Dfile.encoding=UTF-8 \
  -Duser.timezone=Asia/Shanghai"
```

### Nginx 负载均衡

- **策略**: 轮询 (Round-Robin)
- **连接保持**: 32 个 keepalive 连接
- **Gzip 压缩**: JSON/CSS/JS 自动压缩
- **日志格式**: JSON 格式(便于 ELK 采集)

## 监控配置

### Actuator 端点

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics
  endpoint:
    health:
      show-details: always
```

| 端点 | URL | 说明 |
|------|-----|------|
| 健康检查 | `/api/actuator/health` | 详细健康状态 |
| 应用信息 | `/api/actuator/info` | 应用版本等 |
| 指标数据 | `/api/actuator/metrics` | JVM/HTTP 指标 |

### 日志管理

所有容器使用 JSON 格式日志输出:

```bash
# 查看应用日志
docker compose logs -f --format json crs-app1

# 查看 Nginx 访问日志
docker compose exec crs-nginx cat /var/log/nginx/access.log
```

## 故障排查

### 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| App 实例 unhealthy | MySQL 未就绪 | 检查 `docker compose ps` 确认 MySQL 健康 |
| 连接数据库失败 | 密码错误 | 检查 `.env` 文件或环境变量 |
| 端口冲突 | 80/3306 被占用 | 修改 `docker-compose.yml` 中的端口映射 |
| 内存不足 | JVM 堆配置过大 | 调整 `JAVA_OPTS` 中的 `MaxRAMPercentage` |

### 日志排查

```bash
# 查看所有服务状态
docker compose ps -a

# 查看最近的错误日志
docker compose logs --tail=50 --since=10m

# 进入容器调试
docker compose exec crs-app1 sh
docker compose exec crs-mysql mysql -u root -p
```

### 恢复操作

```bash
# 强制重建所有容器
docker compose down
docker compose up -d --build

# 仅重建某个服务
docker compose up -d --build crs-app1

# 清理 Docker 缓存
docker system prune -a
```

## 生产环境注意事项

1. **修改默认密码**: 务必在 `.env` 中设置强密码
2. **JWT 密钥**: 使用随机生成的长密钥(至少 32 字符)
3. **HTTPS**: 生产环境需配置 TLS(可在 Nginx 层添加 SSL)
4. **备份策略**: 定期备份 MySQL 数据卷
5. **监控告警**: 建议集成 Prometheus + Grafana 监控
6. **日志收集**: 建议使用 ELK 或 Loki 收集日志
