> 版本：v1.0

## 1. 项目概述

### 1.1 项目目标

Wylie College（怀利学院）原有一套基于大型机（mainframe）技术的旧学生注册系统，因联邦拨款缩减，无法一次性整体更换。本项目目标：

- 开发一套基于 B/S 架构的课程注册系统，替代原有大型机遗留系统
- 学生可在校园局域网内通过浏览器选课并查看电子成绩单
- 教授可登录系统登记授课课程并为学生录入成绩
- 注册主任（Registrar）负责维护学生/教授信息、关闭注册，并触发账单流程
- 系统需与遗留课程目录数据库（Course Catalog）集成，采用只读方式访问

### 1.2 技术架构

| 层级 | 技术选型 |
|---|---|
| 前端 | Vue 3 + Vite 8 + Element Plus + Pinia + Vue Router |
| 后端 | Spring Boot 3.3 + Java 21 + Spring Security + JPA/Hibernate |
| 数据库 | 开发环境: H2 内存库 / 生产环境: MySQL 8.x |
| 认证 | JWT (jjwt 0.12) + BCrypt 密码哈希 |
| 架构模式 | 三层 B/S 架构（前端 → REST API → 数据持久层） |

**关键设计决策：**
- User 实体采用单表策略（非 JOINED 继承），简化查询
- 集中式审计日志（AuditService），记录登录/选课/成绩等操作
- H2/MySQL 双 Profile，开发环境用内存库，生产环境用 MySQL
- 课程目录采用 Adapter 模式 + 中间层缓存，满足遗留系统 ≤10s 延迟约束

## 5. 风险管理

### 5.1 技术风险

| 风险 | 概率 | 影响 | 应对措施 |
|---|---|---|---|
| 并发选课超卖（>10 人） | 高 | 高 | 使用 JPA 乐观锁或数据库行锁，容量校验与选课写入在同一事务内完成 |
| 遗留系统集成延迟超标（>10s） | 中 | 高 | 实现中间层缓存（本地物化视图 + 请求级缓存），降低对遗留库的直接访问频率 |
| JWT 安全漏洞 | 低 | 高 | 使用强密钥、设置合理过期时间、实现 Token 刷新机制 |
| 前端与后端接口不一致 | 中 | 中 | 迭代初期定义 REST API 规范，前后端并行开发时定期联调 |
| H2 与 MySQL 兼容性差异 | 低 | 中 | 开发阶段使用 MySQL 兼容模式测试，避免使用 H2 特有语法 |

### 5.2 进度风险

| 风险 | 概率 | 影响 | 应对措施 |
|---|---|---|---|
| Close Registration 算法复杂度超出预期 | 高 | 高 | 提前在迭代 2 阶段设计算法原型，迭代 4 专注实现和测试 |
| 组员因其他课程占用时间 | 中 | 中 | 每周固定进度会议，及时调整分工；核心模块由 2 人负责 |
| 需求变更（如新增业务规则） | 低 | 中 | 需求冻结后变更需全组评审，评估影响后决定是否采纳 |
| 测试阶段发现大量缺陷 | 中 | 高 | 开发阶段同步编写单元测试，提前发现并修复缺陷 |
| 演示前一天系统崩溃 | 低 | 高 | 提前 2 天完成最终版本，预留修复时间 |

### 5.3 应对措施总结

**风险预防机制：**
1. **每日站会**：每天 10 分钟同步进度，及时暴露阻塞问题
2. **代码评审**：核心模块（选课校验、Close Registration）必须经过代码评审
3. **持续集成**：每次提交自动运行单元测试，确保不引入回归缺陷
4. **版本控制**：使用 Git 分支策略（main / develop / feature），保护主分支
5. **备份策略**：每日提交代码到远程仓库，重要里程碑打 Tag

**应急响应流程：**
1. 发现阻塞问题 → 当日站会报告 → 组长评估影响 → 调整分工或方案
2. P0 级缺陷 → 立即修复 → 回归测试 → 重新部署
3. 进度落后 → 削减非核心功能 → 保证核心用例优先完成
