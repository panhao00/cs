1. 打开 http://localhost:5173 → 自动跳转登录页
2. **演示学生登录:**
   - 点击 "Student" 标签 → 自动填充 `student / student`

- **密码安全**: 密码使用 BCrypt 哈希存储,不可逆
- **暴力破解防护**: 连续失败 5 次锁定账户 15 分钟

## 2. Register for Courses 学生选课 (4 分钟)

> 用 `student / student` 账号登录

### 步骤

1. 点击仪表盘 "选课" 快捷入口 → 进入选课页面
2. **展示课程目录:**
   - 页面显示本学期 (2026-FALL) 可选课程列表
   - 包含: CS101 (计算机导论)、CS201 (数据结构)、CS301 (算法设计)、MATH101 (高等数学)、ENG101 (大学英语)
   - 每门课显示: 课程编号、名称、学分、容量、上课时间
3. **选择主选课程 (PRIMARY):**
   - 选择 CS101 (计算机导论) → 主选
   - 选择 CS201 (数据结构) → 主选
   - 选择 MATH101 (高等数学) → 主选
   - 选择 ENG101 (大学英语) → 主选
4. **选择备选课程 (ALTERNATE):**
   - 选择 CS301 (算法设计) → 备选
5. **点击 "保存课表":**
   - 课表状态: DRAFT (草稿)
   - 可继续修改
6. **点击 "提交课表":**
   - 系统执行校验:
     - ✅ 先修课校验: CS201 需要 CS101 (如果 CS101 已选则通过)
     - ✅ 容量校验: 每门课容量 10 人
     - ✅ 时间冲突检测: 检查 MWF/TR 时间段是否重叠
     - ✅ 主选数量校验: 最多 4 门主选
     - ✅ 备选数量校验: 最多 2 门备选

### 演示要点

- **先修课校验**: CS201 (数据结构) 需要先修 CS101 (计算机导论),如果未选 CS101 则提交失败
- **容量校验**: 每门课最大容量 10 人,超出则提交失败
- **时间冲突检测**: 自动检测课程时间是否重叠
- **主选/备选限制**: 最多 4 门主选 + 2 门备选
- **课表状态**: DRAFT (草稿) → COMMITTED (已提交)

> **截图描述**: 课程列表(带复选框) → 选择课程(主选/备选标签) → 保存课表 → 提交结果(成功/失败详情)

## 7. Close Registration 关闭注册 (2 分钟)

> 用 `registrar / registrar` 账号登录

### 步骤

1. 点击仪表盘 "关闭注册" 快捷入口 → 进入关闭注册页面
2. **预览关闭注册结果:**
   - 点击 "预览" 按钮
   - 页面显示各课程开设的预览状态:
     - CS101: 有教授 + 5 人 ≥ 3 → 将被 COMMITTED
     - CS201: 有教授 + 4 人 ≥ 3 → 将被 COMMITTED
     - CS301: 无教授 → 将被 CANCELLED
     - MATH101: 有教授 + 2 人 < 3 → 将被 CANCELLED
     - ENG101: 有教授 + 6 人 ≥ 3 → 将被 COMMITTED
3. **执行关闭注册:**
   - 点击 "执行关闭" 按钮
   - 系统执行完整算法:
     - **步骤 1**: 校验注册状态
     - **步骤 2**: 检查教授指派 + 最小人数 → commit/cancel
     - **步骤 3**: Leveling 课表均衡
     - **步骤 4**: 二次检查 + 取消仍不足最小人数的开设
     - **步骤 5**: 通知 Billing 系统
     - **步骤 6**: 通知所有学生
4. **展示结果:**
   - 显示关闭注册结果统计:
     - 已提交: X 门
     - 已取消: Y 门
     - Leveling 提升: Z 个备选为主选
   - 显示各开设的最终状态

### 演示要点

- **Commit/Cancel 算法**: 有教授 + ≥3 人 → COMMITTED; 无教授或 <3 人 → CANCELLED
- **Leveling 课表均衡**: 为学生课表补充备选课程
  - 学生有 DRAFT 状态的课表
  - 主选课数未满上限 (4 门)
  - 按备选列表顺序尝试选入第一个可用备选开设
- **二次检查**: Leveling 后仍不足最小人数的开设被取消
- **通知系统**: 学生收到课程取消/选课成功通知
- **Billing 通知**: 模拟向账单系统发送事务

> **截图描述**: 预览结果 → 执行关闭 → 结果统计 → 通知列表

# 执行关闭注册

> 用 `student / student` 账号登录 (先完成选课使热门课程满员)

### 步骤

2. **展示我的候补列表:**
   - 页面显示当前学生加入候补的课程 (为空时显示"暂无候补课程")
   - 每项显示: 课程号、课程名称、排队位置、状态、加入时间
3. **加入候补 (通过选课页触发):**
   - 回到选课页面,选择一门已满员的课程 (如 CS301,容量 10/10)
   - 系统提示"课程已满,加入候补名单?" → 确认
   - 回到候补页面 → 刷新 → 显示排队位置 (如"第 1 位",状态 WAITING)
4. **重复加入冲突:**
   - 再次尝试加入同一课程候补 → 提示 409 冲突 (已在候补名单)
5. **取消候补:**
   - 点击该条候补记录 "取消候补" 按钮
   - 确认后状态变为 CANCELLED (或从列表移除)

### 演示要点

- **满员判断**: 仅当课程 `enrolled >= maxCapacity` 时允许加入候补
- **排队机制**: 按加入时间顺序分配 `position`,FIFO 递补
- **先修课校验**: 递补时校验先修课,不满足则跳过
- **自动通知**: 递补成功后自动发送通知

> **截图描述**: 候补列表(排队位置标签) → 选课页满员提示 → 确认加入候补 → 取消候补确认框

## 9. Submit Course Review 课程评价 (1.5 分钟)

> 用 `student / student` 账号登录

### 步骤

1. 点击仪表盘 "课程评价" 快捷入口 → 进入评价页面 (或从课程详情页进入)
2. **提交评价:**
   - 选择一门已修读的课程 (如 CS101)
   - 选择评分 (1-5 星) + 填写评论
   - 点击 "提交评价" → 评价保存成功
3. **评分范围校验:**
   - 尝试提交评分 0 或 6 → 返回 400 错误 (评分需在 1-5 之间)
4. **重复评价冲突:**
   - 对同一门课再次提交评价 → 返回 409 冲突 (每人每门课仅一条评价)
5. **修改/删除评价:**
   - 找到已提交的评价 → 点击 "修改评价" → 更新评分和评论 → 保存成功
   - 点击 "删除评价" → 确认 → 评价移除
6. **查看平均评分:**
   - 课程列表/详情页展示每门课的平均评分 (多人评价后计算)

### 演示要点

- **评分校验**: 评分范围 1-5,超出返回 400
- **唯一性约束**: 同一学生同一开设仅一条评价 (重复提交 409)
- **平均分计算**: 按开设、按课程两个维度的平均评分
- **角色权限**: 仅 STUDENT 可提交评价

> **截图描述**: 评价表单(星级评分+评论) → 提交成功 → 我的评价列表 → 平均评分展示

## 技术亮点总结 (2 分钟)

### 1. 三层 B/S 架构

```
浏览器 → Vue 3 前端 (Vite + Element Plus + Pinia)
         → Spring Boot 3.3 REST API (Java 21)
         → JPA Repository (H2/MySQL)
```

### 2. 安全架构 (三层防护)

| 层 | 技术 | 说明 |
|---|---|---|
| 认证层 | JWT (jjwt 0.12) + BCrypt | 无状态认证,密码单向哈希,连续失败 5 次锁定 15 分钟 |
| 授权层 | Spring Security + RoleGuard | 角色 RBAC (STUDENT/PROFESSOR/REGISTRAR) |
| 数据层 | DTO 过滤 + 水平越权防护 + 审计日志 | SSN/密码不暴露,用户只能操作自己的数据,敏感操作留痕 |

### 3. 并发控制

- **乐观锁**: CourseOffering.version 字段防止超卖
- **悲观锁**: @Transactional 注解保证事务一致性
- **容量校验**: 提交时检查 enrolled < maxCapacity
- **候补队列**: 满员后 FIFO 排队,退选自动递补

### 4. 数据库双模式

| 环境 | 数据库 | 说明 |
|---|---|---|
| 开发 | H2 内存库 | 零配置,快速启动 |
| 生产 | MySQL 8.x | 事务、索引优化 |

### 5. 测试覆盖

### 7. 业务规则

| 规则 | 描述 | 实现位置 |
|---|---|---|
| R01 | 课程开设最多 10 人,最少 3 人 | CourseOffering.maxCapacity |
| R02 | 每位学生每学期最多 4 门主选 + 2 门备选 | ScheduleService |
| R03 | 选课前必须通过先修课 | ScheduleService.hasPassedPrerequisite() |
| R04 | 选课时检测时间冲突 | TimeConflictUtil.isConflict() |
| R05 | 注册阶段: open → add-drop → closed | RegistrationPhase |
| R15 | 课程满员时学生可加入候补,按 FIFO 递补 | WaitlistService |
| R16 | 每位学生每门课仅一条评价 (评分 1-5) | ReviewService |
| R17 | 课程推荐综合先修链/热门度/院系/偏好四维度 | RecommendationService |
| R18 | 系统设置仅 REGISTRAR 可读写 | SystemSettingService |
| R19 | 审计日志记录全部敏感操作 | AuditService |
| R20 | 成绩加密存储 (环境变量密钥) | GradeEncryptionConverter |
